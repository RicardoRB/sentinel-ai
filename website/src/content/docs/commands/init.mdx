title: init
description: Create sentinel.toml and select integrations.

`sentinel init` creates `sentinel.toml` using an interactive wizard or explicit options.

To set up Sentinel together with your coding agent instead, install the
[agent skills](/integrations/agent-skills/). The `sentinel-init` skill inspects the project, explains
each choice for this codebase, and runs `init` with explicit options after you approve the
`--dry-run` plan.

```sh
sentinel init [-C <dir>] [--preset <standard|strict>] [--integration <none|agent>[,...]] [--quality-hooks] [--remove-quality-hooks] [--gate <id>[,...]] [--tool openspec] [--openspec-validation <openspec|openspec-archived>[,...]] [--install-tool <tool|gate>[,...]] [--architecture <style>] [--overwrite] [--dry-run] [--accept-compatibility-updates] [--yes]
```

`agent` accepts the IDs documented for [`integrate`](/commands/integrate/), including `codex`, `cursor`,
`copilot`, `gemini`, `windsurf`, `cline`, `factory-droid`, and `amp`.

The gate selector accepts supported [gate IDs](/configuration/gates/). `none` is exclusive with
agent integrations. `archunit` prompts for Layered, Hexagonal, or Clean architecture and creates a
minimal `ArchitectureTest.java` only if one is absent. If test sources already contain ArchUnit
classes ending in `Test` or `Tests`, init reuses them and configures the gate to run those classes
instead of generating a duplicate. Existing configurations are preserved unless
overwrite is confirmed or `--overwrite` is supplied. Initialization does not install tools or run
gates. `standard` and `strict` presets pre-select their offline gates; `custom` starts with no gates selected.
The gates you confirm are exactly the gates configured: unticking a pre-selected preset gate removes its
`sentinel.toml` section, Maven declarations, and rule file, while the preset's rules still apply to the
remaining gates. `zap` writes a `<TARGET_URL>` placeholder that you must replace
with an authorized target before `check` will run it. For `format`, `enforcer`, `license`, `api-compat`, and
`pmd`, missing Maven plugins are added to `pom.xml` using Sentinel's embedded Java/Maven compatibility catalog.
For Gradle projects, equivalent pinned plugin declarations are added to `build.gradle` or
`build.gradle.kts` using the detected DSL, and the Gradle Wrapper is preferred when available.
Existing compatible plugin versions are preserved. Incompatible managed plugins show the current version,
selected compatible version, detected constraints, and affected file before asking for consent. `--yes`
(see [How questions are answered](#how-questions-are-answered)) also accepts these validated compatibility
updates without prompting; it does not bypass unresolved prerequisites
or install standalone binaries such as Semgrep, Gitleaks, Trivy, or ZAP. Missing Trivy, Gitleaks, or
Semgrep tools may be installed with explicit per-tool consent when Homebrew or pipx is available;
use `--install-tool <gate>` for non-interactive consent. ZAP has manual guidance only. Declined updates leave the POM
unchanged and report that the selected gate was not reconfigured. Preset rule files are Sentinel-owned;
unmarked existing files are preserved and reported. With `--preset`, `--gate` only adds gates to the
preset's set; it never removes preset gates. `-C <dir>` selects the
project directory. Exit codes: `0` success, `2` invalid usage or
inability to initialize (including cancelled or invalid selection).

Maven plugins are added only to the project-level `<build><plugins>` and dependencies only to the
project-level `<dependencies>`. Profiles, `pluginManagement`, `dependencyManagement`, and plugin
dependencies are never edited, and missing `<build>`, `<plugins>`, or `<dependencies>` sections are
created. New declarations match the file's indentation. The rest of `pom.xml` is left byte for byte as
it was. Before writing, Sentinel checks the edited `pom.xml` in-process, without running Maven or
fetching anything: the file must be well-formed XML, and each added declaration must contain only
elements Maven allows there. If a check fails, `pom.xml` is not written, the error names the tool being
added, and init rolls back its other changes. POMs with a `DOCTYPE` declaration are not edited
automatically; add those declarations by hand. Compatibility version updates change only the managed
plugin's own project-level `<version>`. A plugin declared only inside a profile is reported as not
reconfigured.

Init-generated configurations assign gates to cumulative execution phases. Fast gates (`format`,
`checkstyle`, `pmd`, and `gitleaks`) belong to `default`, `pre-commit`, `pre-push`, and
`ci`. Slower local gates belong to `pre-push` and `ci`; environment-dependent gates belong to `ci`,
and custom commands belong to `pre-push` and `ci`. The `default` profile is intentionally the same
fast tier as `pre-commit`, while `ci` contains every selected gate. `compile` is a slower local gate
and therefore runs only in `pre-push` and `ci`. Init does not generate a CI workflow.

The generated `gitleaks` command writes a redacted SARIF report so `sentinel check` can attach
structured findings (file, line, and rule) to a failed gate:

```toml
[quality-gates.gitleaks]
command = ["gitleaks", "detect", "--no-banner", "--redact",
           "--report-format", "sarif", "--report-path", "target/gitleaks.sarif"]
```

Gradle projects use `build/gitleaks.sarif`. Sentinel creates the report directory before the gate
runs, so the gate works on a fresh clone. Configurations generated by earlier versions keep working
without findings; re-run `sentinel init` or add the four report arguments to enable them.

Quality hooks are separate from agent integrations and are opt-in. Pass `--quality-hooks` to add
Sentinel-managed checks to `.git/hooks/pre-commit` and `.git/hooks/pre-push`. Each managed section is
inserted after the shebang and before existing user logic; it does not replace the hook. The
pre-commit section runs `sentinel check --profile pre-commit`, and the pre-push section runs
`sentinel check --profile pre-push`. Re-run the option to refresh the managed sections. Use
`--remove-quality-hooks` to remove only Sentinel's marked sections, preserving user content,
executable permissions, and other Sentinel integrations. A malformed or duplicate quality-hook marker
is reported as a conflict and left unchanged.

On supported macOS and Linux terminals, use Up/Down to move, Space to toggle, and Enter to confirm.
Press `q`, `Q`, or Ctrl+C to cancel. On Windows, piped input, or when raw terminal mode is unavailable,
the wizard uses numbered prompts instead. Numbered prompts show pre-selected items as `[x]`; each number
you enter toggles that item, and an empty line accepts the pre-selection. For example, after choosing
`standard`, entering the number of `pmd` configures every standard gate except `pmd`.

## Wizard tips

- Each question starts with `Step N of M`. The total can grow when an answer adds a follow-up question,
  such as the architecture style after you select `archunit`.
- Press Enter to accept the default shown in brackets: `Enter=1` (`standard`) at the preset question
  and `Enter=layered` at the architecture question.
- Gates whose tool is not installed are marked `[unavailable]` in the gate list. If you select one
  anyway, init configures it and prints how to make it available, for example
  `Selected quality gate 'semgrep': UNAVAILABLE - ...`.
- The arrow-key menus redraw in place, so your earlier answers stay on screen.

### Reconfiguring

Run `sentinel init` again and answer `y` to the overwrite question (or pass `--overwrite`) to change an
existing setup. The preset question defaults to the preset recorded in `sentinel.toml` (`custom` when
none is recorded), and the gate list starts with the gates that are currently enabled, so changing one
gate takes a couple of key presses. Integrations, hooks, tools, and the architecture style are asked
as usual. If the existing file can't be read, the usual defaults apply. Answering `n` keeps the file
and prints `Kept existing sentinel.toml. No changes were made.`

### Gate tool installation

When a selected external gate tool is unavailable, the wizard offers one Yes/No installation
question per resolvable tool. No is the default; blank input or end of input declines. Homebrew is
supported for Trivy, Gitleaks, and Semgrep, and pipx is a fallback for Semgrep. ZAP's
`zap-baseline.py` has manual guidance only. In non-interactive mode, explicitly consent with
`--install-tool <gate>` (for example `--install-tool trivy`); `--yes` never installs tools.
`--dry-run` lists commands but runs none. `sentinel check` never installs gate tools.

## Review and dry run

Before writing anything, init works out exactly which files it would change. On a terminal it shows
that plan and asks `Proceed? [Y/n]`. Press Enter or answer `y` to apply it. Answer `n`, or end the
input, and nothing changes. The review is skipped with `--yes` and when input is not a terminal.

```console
Sentinel will make these changes:

  create     sentinel.toml
  modify     pom.xml
               + maven-pmd-plugin 3.28.0
               ~ spotless-maven-plugin 1.0.0 -> 3.10.3 (requires approval)
  create     config/pmd-ruleset.xml
  keep       config/checkstyle.xml  (user-owned, not changed)
  create     .git/hooks/pre-commit
  create     .claude/settings.json

Proceed? [Y/n]:
```

The plan lists every file init would create, modify, or remove, including agent-integration files and
Git hooks. For `pom.xml` or the Gradle build file it names each plugin it would add, with its version,
and each managed plugin whose version it would update. Updates that still need approval are marked
`(requires approval)`. User-owned files that init leaves alone are listed as `keep`. A user-owned file
that would block initialization is listed as `conflict`, and init stops with exit code `2` before
writing anything.

`--dry-run` resolves your answers the same way, prints the plan, and exits with code `0` without
writing files, installing OpenSpec, or asking for compatibility approval:

```console
sentinel init --dry-run --preset strict --integration none --architecture layered
```

`--accept-compatibility-updates` approves validated Maven compatibility updates without prompting,
without the other effects of `--yes`.

## How questions are answered

Each question is answered by the first of these that applies:

1. The option that answers it, such as `--preset`, `--gate`, `--integration`, `--architecture`,
   `--tool`, or `--quality-hooks`.
2. Its default, when `--yes` is given: preset `standard` with its gates, integration `none`, no tools,
   OpenSpec validations, or installation, no quality hooks, and architecture `layered`. `--yes` never
   overwrites an existing `sentinel.toml` (use `--overwrite`) and never installs OpenSpec (use
   `--install-tool openspec`).
3. An answer read from input.

On a terminal, options never hide the questions they don't answer, so
`sentinel init --integration claude-code` still asks for the preset, gates, Tools, and quality hooks.
Without a terminal, for example in CI, when `--preset`, `--gate`, or `--integration` is given, init
reads nothing: unanswered questions take their defaults, so an open but silent standard input can't
make it wait. Without options, answers can be piped, for example `printf '1\n1\n\n' | sentinel init`.

The preset and gate selection is the only required answer. If input ends before it, or it is missing
in a non-interactive run, init exits with code `2` and suggests `--preset`, `--gate`, or `--yes`. If
input ends at any other question, init uses its default and continues, except at the OpenSpec
installation prompt, where initialization is cancelled and no files are changed.

On a terminal, an invalid answer, such as `4` at the preset question, an out-of-range number, or an
empty gate selection, shows the error and asks the same question again, keeping your earlier answers.
The raw-key menus stay open after an empty confirmation. With piped input, an invalid answer fails
immediately with exit code `2` and no changes.

The wizard has a separate optional Tools screen. OpenSpec, its active validation
(`openspec validate --all --strict --no-interactive`), and its archived validation
(`openspec validate --archived --no-interactive`) are unselected by default. Selecting a tool or
validation is not installation consent. `--install-tool openspec` is explicit consent; without it
Sentinel only writes selected validations and reports manual remediation.
## Troubleshooting with verbose diagnostics

Add `--verbose` to the root command or `init` command to route initialization decisions to stderr.
Diagnostics identify ownership conflicts, applied changes, and rollback outcomes without printing
file contents:

```console
sentinel --verbose init
sentinel init --verbose
```
