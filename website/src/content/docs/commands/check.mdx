---
title: check
description: Run configured quality gates.
---

```sh
sentinel check [-C <dir>] [--format text|json] [--profile <name>[,...]] [--fail-fast] [--learn-after <n>]
```

Checks run in configuration declaration order. `default` is selected when no profile is provided;
repeat `--profile` or provide comma-separated names to select the union. At least one enabled gate
must match. All selected gates run even when an earlier one fails. A gate whose standalone tool is
missing (for example `gitleaks`) is reported as unavailable with install guidance; an enabled
`zap` gate without an explicit `-t <url>` target is a configuration error.
Use `--fail-fast` to stop after the first gate that fails, is unavailable, or encounters an execution
error. Later selected gates are listed as skipped (`not run (fail-fast)`). Without the option, all
selected gates run as usual.

Text output starts with the Sentinel version, then reports each gate as it completes, followed by a
summary. On an interactive terminal, the running gate line is replaced in place by its final status.
When output is redirected, `NO_COLOR` is set, or `TERM=dumb`, each gate is printed once on completion
without ANSI cursor-control sequences. Failed gates include their command and captured output tail.

```text
Sentinel 1.2.3

✓ Checkstyle
✗ SpotBugs

Quality Gate: FAILED
1 passed · 1 failed · 0 skipped
```

Use `--format json` in scripts; only the JSON report goes to stdout and diagnostics go to stderr.
The format values are exactly `text` and `json`; an unknown value is a usage error. `--learn-after`
must be at least `1`, and invalid values are reported as usage errors without emitting a partial
report.
Learning is opt-in: `--learn-after <n>` records recurring gate failures in `.sentinel/learning.json`.
A failure is counted once per failing episode; when a recurring failure later passes, the text report
adds a `Learning` section asking the agent to add a preventive rule to `AGENTS.md`. Sentinel never
edits that file, and learning prompts do not change the gate exit code.
See [JSON output](/reference/json-output/) and [exit codes](/reference/exit-codes/). `-C <dir>` runs
against a project directory other than the current one. Exit `0` means all gates passed, `1` means
at least one gate failed, and `2` means Sentinel could not run (for example, invalid configuration).
## Verbose diagnostics

Use `--verbose` before or after `check` to send compact execution diagnostics to stderr:

```console
sentinel --verbose check
sentinel check --format json --verbose > report.json 2> diagnostics.log
```

Diagnostics describe discovery, profile selection, gate lifecycle, fail-fast skips, and safe
process status metadata. They do not contain gate stdout/stderr, command arguments, configuration
contents, or credentials. Gate failures remain the normal check report and are not warnings by
themselves.
