```sh
sentinel hook claude-code [-C <dir>] [--learn-after <n>] [--exclude-spec] [--event-stdin]
sentinel hook claude-code [-C <dir>] --guard-approved-specs --event-stdin
sentinel hook native --agent <agent> [-C <dir>] [--event-stdin] [--guard-approved-specs]
```

`sentinel hook` contains the adapters that generated agent integrations call. You normally do not run it
yourself. `sentinel integrate claude-code` creates `.claude/hooks/sentinel-edit-write`, which runs
`sentinel hook claude-code --learn-after 3 --exclude-spec --event-stdin` after Claude Code's edit tools and
when Claude stops.

The native adapter accepts bounded JSON from the supported harnesses, runs quality checks and targeted
OpenSpec validation, and translates guard refusals into the harness response shape. Malformed, missing,
or oversized payloads (over 1 MiB) fail safely and never print payload contents. `--agent` is required
and must be one of the native harness IDs (`codex`, `cursor`, `copilot`, `gemini`, `windsurf`, `cline`,
`factory-droid`, `amp`). See [native harness integrations](/integrations/native-harnesses/).

| Option | Effect |
|---|---|
| `--learn-after <n>` | Learn recurring quality failures after `n` occurrences (default `3`). |
| `--exclude-spec` | Skip the `openspec` and `openspec-archived` gates in the quality check, because spec validation runs separately. |
| `--agent <agent>` | (`native` only) Harness whose payload and response format to use. |
| `--event-stdin` | Read the hook event JSON from stdin. It is ignored when stdin is an interactive terminal. |
| `--guard-approved-specs` | Act as the opt-in `PreToolUse` [approved-artifact guard](#approved-artifact-guard). No quality gates, learning, or spec validation run in this mode. |

Without `--event-stdin`, or when the payload is empty or not valid JSON, the adapter behaves as it always has. It
runs the `default` profile gates as a `PostToolUse` check. When they pass, it returns any learning prompts as
`PostToolUse` context. When they fail, or Sentinel cannot run, it writes the failures to stderr and exits `2`,
which Claude Code shows to the agent so it can fix them.

With an event payload:

- **`PostToolUse`:** a [partial check](/commands/check/) runs for the edited `tool_input.file_path`, then the path
  goes through [`spec validate`](/commands/spec/). Spec findings are reported on stderr with exit `2`, alongside
  any quality failures. An event without a path runs every gate in full.
- **`Stop`:** the full `default` quality check and the configured spec validations run. Findings block the stop
  once, using `decision: "block"`. When `stop_hook_active` is true, or Sentinel cannot run, they are shown to the
  user as a `systemMessage`. This full check also catches files changed by shell commands, which send no edit
  event. The exit code is `0`.

See [Claude Code](/integrations/claude-code/) and [learning](/configuration/learning/).

## Approved-artifact guard

`sentinel integrate claude-code --guard-approved-specs` creates `.claude/hooks/sentinel-openspec-guard`, which runs
`sentinel hook claude-code --guard-approved-specs --event-stdin` before Claude Code's `Edit`, `Write`, `MultiEdit`,
`NotebookEdit`, `Bash`, and `Skill` tool calls. The adapter reads the whole `PreToolUse` payload (up to 16 MiB,
because a `Write` carries the full file) and passes the edited `file_path` or `notebook_path`, the `Bash` `command`
(resolved against the payload's `cwd`), or the `Skill` name to the same checks as
[`spec guard`](/commands/spec/#guarding-approved-artifacts-spec-guard).

| Situation | Output | Exit |
|---|---|---|
| Allowed | Nothing, so Claude Code's own permission handling still applies | `0` |
| Refused | `PreToolUse` JSON with `permissionDecision: "deny"` and the reason as `permissionDecisionReason` | `0` |
| Payload missing from a pipe, larger than 16 MiB, or not a JSON object | A `deny` stating that Sentinel could not inspect the call | `0` |
| Sentinel cannot decide, for example outside a detectable project | The problem on stderr; Claude Code treats it as non-blocking | `1` |
| Any other event, such as `Stop` | Nothing | `0` |

The guard never answers `allow` or `ask`, so it cannot bypass your permission prompts.

## Verbose diagnostics

The inherited `--verbose` option also applies to nested hooks, for example
`sentinel hook claude-code --verbose`. Diagnostics are written to stderr, leaving the hook JSON
response on stdout unchanged. They never include findings, payload contents, or command lines.
