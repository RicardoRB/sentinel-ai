---
title: OpenCode
description: Install Sentinel's OpenCode edit/write plugin.
---

Install with `sentinel integrate opencode`. Sentinel retains the
`.opencode/commands/sentinel-check.md` command and creates
`.opencode/plugins/sentinel-edit-write.js`. The plugin's `tool.execute.after` handler checks `edit`
and `write`; a failed or unavailable check is returned as a non-success result with Sentinel output.
It runs `sentinel check --format json --learn-after 3` from the project directory and appends
learning prompts to the tool result. Ensure `sentinel` is on `PATH` and re-run integration to
refresh an outdated Sentinel-owned plugin.

Generated files contain ownership markers. User-owned targets are never overwritten and a
conflict does not enable a partial integration. Remove with
`sentinel integrate opencode --remove`; only Sentinel-owned generated files are deleted. Hooks
execute trusted repository configuration with your privileges.

## OpenSpec guidance

`sentinel integrate opencode --openspec-guidance` also installs the Sentinel-owned skill
`.opencode/skills/sentinel-openspec-workflow/SKILL.md`. It tells OpenCode to plan and archive
changes through OpenSpec's official `/opsx-*` workflows, that `sentinel check` decides whether
implementation is acceptable while `/opsx-verify` is only advisory, and that approved specs must
not be changed to make failing code pass.

Sentinel does not install, update, or edit OpenSpec's own files. The official
`.opencode/commands/opsx-*` commands, `.opencode/skills/openspec-*` skills, and
`openspec/config.yaml` stay under OpenSpec's and your control. See
[integrate](/commands/integrate/#openspec-guidance) for prerequisites and the steps a human must
run.
